About

My work sits where machine learning meets engineering. I care about choosing models for good reasons: interpretable GAMs over black boxes when inspection matters, proper hypothesis tests for drift, and held-out test sets that stay untouched until the very end. I also insist on wrapping models in config-driven, tracked, containerised pipelines.

Lately I've been working on LLM retrieval systems (hybrid dense + lexical search, contextual embeddings, LLM evaluation), systematic hyperparameter tuning for vision transformers, and NLP applications.

Projects

Paper Search

paper-search

Hybrid semantic search and Q&A over research papers. Combines FAISS dense retrieval with BM25 via reciprocal rank fusion, enriches chunks with LLM-generated context, answers with a local Qwen model, and scores answers with a validator pass. Includes a Streamlit UI and a systematic benchmark suite.

FAISSBM25OllamaStreamlitHydra

ViT for Breast Histopathology

ViT-histo

Fine-tuning a Vision Transformer for tumour / no-tumour classification of tissue patches, following Google's Deep Learning Tuning Playbook: quasi-random sweeps, scientific vs. nuisance parameters, checkpoint selection and an untouched test set.

Test ROC-AUC 0.96 · Brier 0.070
PyTorchTransformersW&BHydra

Insurance Cost MLOps

mlops-cycle

End-to-end lifecycle for an interpretable GAM: Hydra-configured training, MLflow tracking and champion/challenger registry, FastAPI serving on Google Cloud, drift detection with an Anderson-Darling test and a two-proportion Z-test, and live Prometheus + Grafana dashboards.

pygamMLflowFastAPIDockerGrafana

Python Data-Extraction RAG

python-rag-data-science

A fully local RAG assistant for pandas / scikit-learn questions, with Weaviate hybrid search, data-driven chunk sizing, and RAGAS evaluation logged to MLflow -- using a separate judge model to avoid self-preference bias.
